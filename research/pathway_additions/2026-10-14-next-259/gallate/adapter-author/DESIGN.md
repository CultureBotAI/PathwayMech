# Explicit KEGG pseudogene authority prototype

This is an external author proposal based on reviewed commit `b718850b63e4a1d2a14cf521950737c641963e38`. Nothing has been applied to the next258 repository. Implementation in a new next259 worktree requires root's separate authorization. This document is a code design, not scientific review of GalR/GalT regulation or protein function.

The complete issuing original is `KEGG:ppu:PP_2519`, SHA-256 `239bb58885aea1fae6ae2ff387c68f78d76388e6bb261f1e8c2694153a313401`. Its ENTRY is native type `gene`, genome `T00114`; SYMBOL is `gllT`; NAME is exactly `(GenBank) pseudogene`; the annotated span is `2867058..2867060` and NTSEQ is `ccg` of length three. No AASEQ is present.

The proposed `kegg-pseudogene-flatfile` kind is selected explicitly in the authority manifest. `project_pseudogene(raw, url)` is its explicit parser entry point. The existing two-argument `project(raw, url)` remains the complete-CDS entry point, with the same rejection behavior, native projection and CDS requirements. There is no parse-error fallback and no inference of profile from NAME.

Both entry points use the same private field/framing, request, position and sequence-count parser. The pseudogene profile additionally requires ENTRY type `gene`, exactly one NAME line equal to `(GenBank) pseudogene`, and complete absence of AASEQ. A differently annotated gene, a CDS, or a loosely matching pseudogene name is rejected by this profile. The exact organism/locus must match the single official HTTPS request. Genome ID syntax, native fields, position, sequence and whole original are retained and rechecked. As with the existing CDS profile, genome-ID/organism crosswalk truth is a separate source interpretation, not inferred by this adapter.

The shared `native_gene` projection is discriminated by source `kind` and exact native `native_type`. Pseudogene metadata adds `annotation_class: pseudogene` and `sequence_scope: native_annotation_only` and omits `aaseq`. Its NTSEQ is only the issuing annotation, which may be three bases or another positive length. No complete biological gene sequence, translation, product length, terminal stop, functional protein, expression or regulatory action is inferred. Span/count agreement checks the annotation's internal shape only.

The projection retains every ordered native field and the entire original text. The consumer independently reconstructs it from the original, verifies its SHA-256, and compares the entire closed projection. A type/kind swap, erased or untyped owner, alternative label/alias, unexpected sequence or changed owner projection fails. Source assertions include the profile kind as well as full native projection and version. Conflicting CDS/pseudogene observations for one identifier fail in both source orders before selection, including when that identifier is not selected.

The term remains `entity_type: native_gene`, `label_kind: canonical`, label `PP_2519`, and no synonyms. SYMBOL `gllT` stays source annotation. Existing placement checks require a participant with `category: gene` before contextual-label exceptions. A pseudogene cannot become a protein, complex, reaction, taxon or record node through this adapter.

The patch touches five files: the shared KEGG parser, authority consumer, source snapshot builder, identifier documentation and a new focused test file. No schema, identifier policy, snapshots, manifest entries, pathway records, governed files or previous test files are changed. Root will decide the maintained source manifest, evidence metadata and record curation after code review.

Verification uses all 432 existing selected CDS/identifier/builder regressions plus 137 new tests. New cases cover explicit profile selection, CDS/pseudogene swaps, request/locus/organism mismatch, exact annotation class, missing/duplicate/native fields, sequence count/alphabet/span/framing, full projection/hash reconstruction, cross-owner conflicts before selection, untyped-owner rejection, canonical labels, gene-only placement and atomic output preservation. A direct replay of the actual PP_2519 original passes the explicit producer/consumer path while the default CDS parser rejects it. The three existing real CDS projections match the baseline byte-derived objects exactly.

The external selector in `real-replay/selectors/` only chooses an identifier for the builder; it is not a maintained pathway or scientific record. Its arbitrary label does not supply authority: the output label is reconstructed from the issuing ENTRY.

The first targeted test run passed 568 tests; a subsequent added default-CDS annotation-preservation case brings the final suite to 569. The first lint attempt rejected one long source-kind documentation line; that attempt and its successful tests remain under `attempt-docstring-lint/`. The final line wrap and exact final checks are recorded separately. This prototype still requires independent code review and later full new-worktree gates before integration.
