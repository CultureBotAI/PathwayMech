# External unnamed MetaCyc reaction authority implementation

The patch adds issuing-source identity support for a genuinely unnamed native small-molecule reaction, and prevents that identity from being used outside a molecular-activity reaction node. It builds on the accepted threonine authority patch; it is not maintained integration or final scientific acceptance.

The exact retained META 27.0 RXN-14904 original is SHA-256 c980c5cbf7b4d7a617246a438658bf7feac22279432c52542992c1338d79e502. Its acquisition receipt establishes the exact HTTPS request and successful body. The XML has no direct common-name; its nested curator/evidence names are not reaction names. The corresponding frame-only HTML remains rejected by the unchanged HTML adapter.

The new metacyc-reaction-xml parser requires one exact HTTPS mirror request, native metadata/query/PGDB/species/software and XML-base agreement, one full non-class Reaction, both Chemical-Reactions and Small-Molecule-Reactions parent classes, a supported direction, and nonempty sides with exact native Compound references. DTD/entity declarations are rejected by the XML parser in supported encodings. Any direct common-name is unsupported, including an empty name or a copied nested name. No accession is hard-coded in implementation code. Named reactions, explicit coefficients/compartments and class participants are intentionally unsupported by this bounded source kind; existing supported adapters retain their behavior.

The emitted term retains only its native frame display token and empty aliases, with label_kind=source_context and entity_type=reaction. Its source metadata carries kind=metacyc-reaction-xml. The identifier loader validates this closed combination. The gate rejects record, taxon, participant and pathway-interface use before it considers contextual-label bypass. Only reactions/category=molecular_activity is eligible, and contextual policy is still required. Same-frame reaction assertion conflicts and cross-kind identity scope conflicts fail before corpus selection.

The new builder/checker fields must be adopted together. They are added only to new reaction identity objects. No pre-existing term/source object, policy entry, pathway record, governed file, original source, shared cache or Git tree was changed. The accepted threonine policy, PubChem adapter and PathBank child support are retained exactly in the baseline and candidate.
