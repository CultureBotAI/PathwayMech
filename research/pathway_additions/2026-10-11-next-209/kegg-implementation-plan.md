# KEGG authority support: bounded implementation plan

Prepared against PathwayMech commit `f3109cf30b55f7559f349403842b14663e98bbe6`. This is an external plan, not an implementation or a claim that the next pathway is scientifically complete. No files in the published 206-record cohort were changed.

## Source facts and intended scope

The retained official M00374 flatfile identifies a Pathway Module named **Dicarboxylate-hydroxybutyrate cycle**. The separately retained official HTML agrees on identity and name. The module lists 14 reaction objects; its abbreviated substrate/product arrows are not complete reaction equations or exact strain evidence.

Fresh official REST retrievals at 2026-10-11T10:45:40Z independently identify **R01196** as a Reaction and **C00138/C00139** as Compound entries. All returned HTTP 200, unchanged official URLs and valid terminated flatfiles. An earlier sandbox DNS failure is retained separately. `acquisition.json` records exact original paths, hashes and safe response metadata. These close the previous scoped absence finding; no missing-body claim remains for these three IDs.

R01196 is a reversible ferredoxin-dependent reaction with coefficients 2 on each carrier state and on H+; module M00374 selects the acetyl-CoA-to-pyruvate direction. C00138 and C00139 provide the names **Reduced ferredoxin** and **Oxidized ferredoxin**, with native alternative names mentioning an iron-sulfur cluster. Neither compound body supplies a formula, exact protein, exact cluster stoichiometry or taxon. Their ChEBI cross-references are 17513 and 17908; a cross-reference alone must not become an unexamined exact structure mapping.

The official API distinguishes M, R and C entry classes and returns flatfiles for `get`; multiple requested entries may share one original response. The plan uses these issuing-authority records, not curated YAML names, filenames, module cross-reference lists, KGML diagram labels or test fixtures. [KEGG API manual](https://www.kegg.jp/kegg/rest/keggapi.html), [entry-format documentation](https://www.kegg.jp/kegg/docs/dbentry.html), [module-field help](https://www.kegg.jp/kegg/document/help_bget_module.html).

## Narrow implementation

1. **Native parser and source kinds.** Add one strict reusable flatfile reader to `scripts/build_source_identifier_snapshot.py`, exposed through three explicit source kinds: `kegg-module-flatfile`, `kegg-reaction-flatfile` and `kegg-compound-flatfile`. Each kind accepts only its own class: `M[0-9]{5}` with ENTRY type `Pathway Module`; `R[0-9]{5}` with `Reaction`; `C[0-9]{5}` with `Compound`. Homogeneous multi-entry batches are allowed. Reject genes, K numbers, maps, organism-specific modules and mixed-type batches in this first implementation. The existing permissive `_kegg_curie()` KGML converter is not suitable for authority parsing.

2. **Parse exact top-level fields.** Read the observed 12-character field column, preserving the distinction between top-level fields, continuation lines and indented reference subfields. Require one nonempty ENTRY and NAME block per entry, valid class/ID agreement, and `///` termination for every entry. Reject orphan continuations, duplicate subjects, repeated ENTRY/NAME blocks, empty entries in non-whitespace content, HTML/error bodies and unterminated trailing text. Ignore unrelated legitimate fields without mining names from them. Validate the whole body before returning terms, so a late malformed entry cannot produce a partially accepted source.

3. **Names and synonyms.** Join NAME continuations with normalized whitespace while preserving chemical punctuation, case, stereochemistry and charge notation. The inspected C00138/C00139 bodies use semicolon-delimited native names across continuation lines: first nonempty name is canonical; subsequent native names are synonyms. Strip only separator semicolons, not meaningful punctuation. Reject empty internal name items; do not split at colons, commas, brackets or parentheses. Do not use DEFINITION, EQUATION, comments, module titles or curator labels as NAME fallbacks. Use canonical KEGG labels in the next record; genuine aliases may be retained as native metadata without allowing arbitrary contextual labels.

4. **Bind URL requests to native identities.** Before corpus filtering, validate each new source's manifest URL as an official `https://rest.kegg.jp/get/<ID>[+<ID>...]` flatfile request, with 1–10 unique, same-class IDs. The parsed ENTRY set must equal the requested set exactly. Reject wrong/extra/missing IDs, unsupported request options, nonofficial hosts and mixed classes. Bare IDs cover all inspected originals; do not add alias or organism-ID parsing speculatively. The complete original response is the hashed artifact; never manufacture separate source bodies by splitting a batch.

5. **Conflict handling.** Keep an independent seen-KEGG registry before the wanted-ID filter. A repeated native identifier with a different canonical name or incompatible native synonym set across manifest sources must fail in either manifest order. The existing generic builder silently keeps the first source for cross-source duplicates; that behavior must not hide a KEGG conflict or promote a contradictory canonical name to a synonym. Prefer one selected source version per KEGG ID; identical repeated assertions may retain one documented provenance source. Reject duplicate IDs inside one body even when identical.

6. **Strict gate integration.** Add `KEGG` to `SOURCE_NAMESPACES` and configure it against `data/identifier_authorities/sources.json` with `policy: canonical`. Commit policy, actual selected original-source manifest entries and the reproducibly built nonempty KEGG snapshot together. Existing schemas already admit the KEGG prefix; no prefix or existence waiver is needed. Do not add a contextual-label exemption for KEGG records or their Rhea/UniProt/CHEBI nodes. Missing KEGG IDs must remain blocking; source-context labels cannot satisfy canonical slots.

7. **Correct exports when R/C nodes are used.** `kgx.py` currently defaults all KEGG nodes to `biolink:SmallMolecule`. Add a narrow full-ID rule for `KEGG:R[0-9]{5}` to `biolink:BiochemicalReaction`; top-level M00374 already exports as Pathway. Preserve explicit category overrides and existing legacy KGML behavior outside the new rule. C00138/C00139 need explicit supported carrier-class categories in the curated record, with original-source justification; do not let the Compound database name imply SmallMolecule or invent a specific protein/cluster. Generic carriers may use the existing `chemical_entity` category where its scope is appropriate. No new category is required merely for KEGG.

8. **Keep URI uses honest.** Explicit `https://www.kegg.jp/entry/<ID>` reference URLs already avoid a new fallback resolver requirement. Existing SSSOM maps the entire KEGG prefix to the compound namespace. If M/R identifiers enter `source_mappings`, correct that bounded URI problem and test all used classes before export; otherwise document that no new M/R mapping is emitted. Do not silently emit module/reaction identifiers as compound URIs. Schema support alone does not prove identifier authority or biological equivalence.

## Meaningful tests

Create `tests/test_kegg_identifier_authority.py` using small synthetic parser fixtures clearly marked as tests; production authority metadata must always come from rehashed originals.

- Positive M, R and C entries; observed multiline compound aliases; homogeneous original-style batches; continued NAME wrapping and indented reference fields; exact original M00374/R01196/C00138/C00139 external replay.
- Missing/blank/duplicate ENTRY or NAME, wrong digit count, lowercase/unsupported identifier, ID/type mismatch, wrong source kind, orphan continuation, missing terminator, trailing error/HTML, duplicate subject, malformed second batch entry and wrong requested-ID set.
- Conflicting labels across two hashed manifest entries in both orders; stable treatment of identical duplicates; cross-reference names never becoming independent terms; curator-only labels never entering authority output.
- Original-body hash mismatch, relative-path safeguards and malformed source must fail without replacing a previous output file. A single missing selected KEGG ID must fail the builder and identifier gate. A canonical-label mismatch and source-context-only label must fail the gate.
- Actual KGX export gives R01196 BiochemicalReaction, M00374 Pathway, and explicitly categorized generic carriers ChemicalEntity; coefficients, directions, descriptions and evidence remain unchanged. Existing KGML import and compound/ChEBI mapping tests continue to pass.
- If SSSOM M/R mappings are added, assert resolvable class-appropriate URIs and unchanged semantics of existing C mappings. Do not add speculative tests for unimplemented classes.

Run the focused parser/gate/KGX tests first, then the repository's required lint, validation, rendering, export and full tests once the next record and sources are frozen. The external original-source replay supplements unit tests; it is not a substitute for independent scientific review.

## Source integration and scientific limits

`proposed-manifest.json` supplies exact originals and relative cache destinations for M00374, R01196, C00138 and C00139, plus an optional already-retained R02164/R09280/R09281 batch. Copy originals unchanged to the external authority cache and bind the full HTTP-body SHA-256. The native responses have no per-entry release designation, so version metadata must say retrieval snapshot and timestamp, not an invented release. Preserve KEGG's license-gated inventory status without inventing an open license.

Build from the complete existing source manifest plus only genuinely selected additions. Compare all baseline source metadata and terms byte-for-byte, retain existing authority coverage, and independently replay newly selected labels. Document supported source kinds in `docs/IDENTIFIERS.md` and the builder docstring. Recheck the next merged baseline before implementation; this plan is anchored to the inspected commit only.

Authority support does not settle organism physiology. The prior Ignicoccus hospitalis full-cycle proposal remains blocked by its step-8 donor mismatch: the inspected activity is supported with artificial reduced methyl viologen, while the available acylating database equations use NADPH. The separately researched Thermoproteus/Pyrobaculum neutrophilum 14-step route has its own primary evidence assessment. R01196 and carrier identities must be assessed within that exact record, with physiological direction and donor scope supported separately. No module-local step IDs, omitted biological steps or invented carrier identities are proposed.
