# Operations and reproducibility

All writes were confined to this new owner. No maintained repository, Git/GitHub, runtime, installed dependency, original discovery/preflight or other agent owner was modified. Public GET requests used the explicitly approved read-only escalation. No account, subscription, CAPTCHA bypass or purchase was used.

1. Discovery intake physically traversed the frozen owner, including hidden/ignored names, and verified 408 listed hashes plus both envelope files; see `results/discovery-intake.json`. Selected report/source copies preserve their original bytes. The later preflight HANDOFF/REVIEW were read, with its source-preparation-only limits.
2. `scripts/acquire.py` processed twelve finite request batches. Every batch command terminated with exit 0; individual HTTP and semantic failures are recorded separately. Original response bodies, response URLs/headers/times and hashes remain intact. HTTP 200 did not suffice for article access. `results/terminal-jobs.json` records observed completed-job outcomes.
3. Public web-tool search/open/find/click responses are retained as exact JSON-encoded returned strings in `receipts/` and selected `originals/` files. They are tool projections, not raw publisher responses. Source text line numbering can vary by retrieval; the actual retained locator applies. The sparse 2013 coverage attempt and corrected complete union are both preserved.
4. Existing `mutool` extracted six PDFs and rendered two EutH pages. Existing `/usr/bin/textutil` extracted three supporting Word files. Commands/stdout/stderr and generated projections remain. No installation or runtime repair occurred. PDF skill guidance was applied read-only, using the available renderer because Poppler was unavailable. Temporary evidence was retained under the task's audit requirement.
5. XML projections use Python ElementTree traversal order, whitespace-collapsed `itertext`, and explicit element tags/IDs. They aid locators; the XML originals control. No projection implies semantic reading of every element. Textutil retains some Word field instructions; those are not scientific assertions.
6. `scripts/build_packet.py` creates the finite reading ledger, 32 structured claim dispositions, acquisition audit, explicit open limits and terminal/visual scope. `scripts/verify_packet.py` separately rechecks the ledger bindings, receipt hashes, main XML presence/absence, 2013 line coverage, projections and claim/source references. It performs no network work or maintained tests.

Preserved failures include the initial sandbox probe, HTTP403/404 and CAPTCHA responses, metadata-only XML, two non-OA supplementary error responses, publisher tool access failures, irrelevant numeric-search results, two mistyped metadata query IDs (excluded from claims), and a local read using an incorrect `.html.text` suffix (exit2; corrected separately). No absence inference was drawn from the failed read or excluded sources.

Nested binary containers are not claimed exhaustively decoded. Three selected Word documents were decoded through textutil; other binary interiors were inspected only as stated (PDF extraction/two pages; one JPEG). No global archive or repository absence search occurred here. Final physical inventory uses a hidden/ignore-independent traversal of this owner; symlinks are rejected. The manifest excludes only itself and the freeze envelope to avoid a hash cycle.

The first packet verifier returned exit1 for one coverage-harness mismatch: a per-file repeated web chunk was overwritten rather than unioned. The original coverage, failed receipt and correction are retained. The corrected union did not change source bytes or the complete main-span result.
