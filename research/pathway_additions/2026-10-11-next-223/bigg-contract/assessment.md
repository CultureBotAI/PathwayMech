# Independent native BiGG authority contract assessment

The three authentic universal JSON bodies support bounded native ID/name authority for BiGG:acmana, BiGG:acmanap and BiGG:ACMANAptspp. Add two explicit source kinds for universal metabolites and universal reactions, with canonical label policy and no contextual exemption. Do not extend support to model endpoints, collection responses, cross-reference namespaces or historical IDs through this change.

This is an independent read-only design assessment, not a review of an implemented adapter or a completed production gate. No tests, downloads, maintained edits, Git or GitHub writes were performed. Input digests are recorded in assessment.json. The proposal digest matches fb5a5c9ed7d772d9df79edf5d997cb9e455adc01bd7f4949a88822ef8d8ff038. The three universal bodies and database-version original match their proposal digests; acquisition receipts report HTTP 200, JSON content and unchanged final URLs. The current builder has no BiGG authority branch and the current policy has no BiGG entry; this bounded search included ignored and hidden files for the specified builder, policy, identifier documentation and identifier test surfaces, not the entire repository.

## Native observations

- acmana: native name N-Acetyl-D-mannosamine; seven top-level keys: old_identifiers, compartments_in_models, name, charges, database_links, bigg_id, formulae. There are 231 model/compartment contexts, charge [0], formulae [C8H15NO6].
- acmanap: native name N-Acetyl-D-mannosamine 6-phosphate; the same seven keys, with 80 model/compartment contexts, charge [-2], formulae [C8H14NO9P].
- ACMANAptspp: native name has two spaces before (periplasm), which ordinary whitespace normalization may collapse. Native reaction keys include models_containing_reaction (66 entries), metabolites, reaction_string and pseudoreaction=false. There is no explicit release or entity-type field in any of these three universal bodies.
- database_version: api_version=v2, bigg_models_version=1.6.0 and last_updated=2019-10-31 10:05:54.157598. The acquisition date is 2026-10-11; these dates describe different observations. The unversioned API is an observed release snapshot, not proof that an immutable 1.6.0 archive was obtained.

## Minimal acceptance contract

1. Bind each source kind to a full-match HTTPS URL of the form https://bigg.ucsd.edu/api/v2/universal/metabolites/<id> or https://bigg.ucsd.edu/api/v2/universal/reactions/<id>. Use a bounded ASCII identifier grammar such as [A-Za-z0-9][A-Za-z0-9_]* for the initial scope. Require native bigg_id to equal the exact requested ID, case sensitively. Reject query strings, fragments, trailing slash, percent-encoded substitutions, credential/port variants, alternative hosts, model/static endpoints, collections and mismatched endpoint class. Preserve actual acquisition receipts; manifest URL validation alone cannot prove redirect history.
2. Parse the unchanged hash-bound body as strict UTF-8 JSON. Require exactly one top-level object. Reject duplicate object keys recursively, trailing content, invalid JSON constants (NaN/Infinity), HTML, lists, nulls, collection wrappers and explicit error/failure envelopes. Do not silently accept duplicate keys even if their values agree. Do not repair bytes or extract JSON from page text.
3. Both types require nonempty string bigg_id and a nonempty resolved string name. Normalize whitespace only for the emitted name; retain case, punctuation and stereochemical text. Reject an ID-only name, unresolved placeholders, explicit error/not-found names, whitespace-only/non-string names and embedded control characters. Do not read a nested metabolite, model, external link or draft label as the canonical name. A narrow explicit placeholder policy is preferable to rejecting any legitimate chemical name containing words such as unknown.
4. Metabolite discrimination: require compartments_in_models, charges and formulae to be lists. Reaction discrimination: require models_containing_reaction and metabolites to be lists, reaction_string to be a nonempty string, and pseudoreaction to be an actual JSON Boolean. Reject opposing class markers, model_bigg_id, results/count wrappers and model-only result surfaces in either universal body. These checks distinguish the supplied native shapes without depending on ID capitalization. An empty native model list need not invalidate an otherwise issued ID; do not infer biology from population counts. A pseudoreaction=true body still has native identity; if intentionally excluded from the bounded adapter, document that restriction rather than interpreting it as nonexistent. No nested stoichiometry or model-context reconstruction is needed for name authority.
5. Optional ignored metadata can remain ignored after strict JSON parsing. In particular, do not recursively emit nested IDs, validate chemical equivalence from database_links, or build aliases from old_identifiers. Neither names under metabolites nor model-specific labels establish separately requested universal authorities. Emit one (BiGG:<exact-id>, native-name, []) assertion per input.

## Database-version binding

The parent's proposed required BiGG-only version_source descriptor is appropriate. It should identify a relative cache path, exact URL https://bigg.ucsd.edu/api/v2/database_version and SHA-256 of the complete original body. Apply the same path safety and digest checks used for the primary body, and validate the descriptor before corpus selection. Reject missing companion fields, absolute/traversal paths, invalid or mismatched hashes and unsupported descriptor types. If symlink containment is added, apply it deliberately and consistently with the existing cache contract rather than accidentally rejecting a valid established cache.

Parse the companion with the same strict JSON rules. Require a single object with api_version exactly v2, a nonempty numeric dotted release string in bigg_models_version, and the native last_updated timestamp as a valid nonempty timestamp string. Reject wrong API/version/error/list bodies. Require the release portion of manifest version to equal bigg_models_version exactly. The proposal's literal format, BiGG Models 1.6.0; retrieved 2026-10-11, can be enforced with a full-match grammar and a valid calendar date; a free-text string merely containing 1.6.0 is insufficient. The retrieval date remains acquisition metadata, not an inference from last_updated. Record and compare observed last_updated as part of companion consistency, without claiming a timezone the original does not supply.

Keep version_source in the maintained source manifest and preserve the companion original plus acquisition receipt externally. This retains rebuildable linkage while existing snapshot metadata can remain unchanged. Do not repurpose sha256_scope: that field describes the artifact covered by the main digest, not a second provenance dependency. If standalone snapshot consumers must audit the companion without the manifest, an explicit additional metadata field can be designed separately. No standalone companion authority term is needed.

Validate the companion for every BiGG input, including inputs that yield no selected term. Shared identical companions are fine. If one build sees disagreeing native release/last_updated assertions for a purported shared database observation, fail rather than selecting whichever appears first. Equivalent JSON serialization can have different body digests, so consistency should compare the validated native release tuple, while provenance retains each original digest.

## Conflicts and selection

Add BiGG to the builder's required-source namespace set so an unprovided BiGG ID fails even if its CURIE is syntactically valid. Use canonical policy in identifier_policy.yaml and the normal empty-namespace and missing-ID guards. No contextual exception is justified by these bodies.

Before checking wanted IDs, track each BiGG CURIE's endpoint class, normalized native name and version observation. Fail conflicting names or cross-class collisions, even for IDs outside the selected corpus and even when the names happen to agree across metabolite/reaction classes. Do not hide conflicts behind the existing first-source selection behavior. Matching repeated assertions may retain first-source provenance without alias merging. Independently hash and validate every input and companion before output publication. A non-BiGG adapter emitting BiGG-prefixed assertions must not bypass the native-kind guard.

Case-preserving whitespace normalization is sufficient for comparing duplicate native names. The final label gate already applies its documented Unicode, whitespace and letter-case comparison; that does not justify accepting contradictory issuing names inside the builder.

## Scientific boundaries to preserve

acmana's universal native InChI Key is MBLBDJOUHNCFQT-XAMCCFCMSA-N. The supplied proposal records CHEBI:17122 as MBLBDJOUHNCFQT-WCTZXXKLSA-N. Preserve this explicit discrepancy. The assessment independently re-read the BiGG original but did not re-query ChEBI or infer which structure is correct. A matching displayed compound name and a CHEBI:17122 database link do not establish exact structural equivalence. Do not silently rewrite either annotation, promote an xref to an authority mapping, or merge the nodes. acmanap's cited matching key does not resolve acmana's discrepancy.

The universal reaction_string contains the reversible presentation entity &#8652;. The independently supplied iML1515 reaction JSON has model_bigg_id=iML1515 and results[0] lower_bound=0, upper_bound=1000 with a forward presentation entity &#x2192;. Its gene rule is b2415 and b1818 and b2416 and b1817 and b1819. These model-specific direction, compartments, stoichiometry and gene-rule assertions stay separate from universal name authority. The reaction name itself establishes none of these claims. Reject the model body as universal authority even if bigg_id and name match. No biochemical, strain, pathway-membership, physiological-direction or chemical-equivalence inference is added by this adapter.

## Meaningful future negatives

These are recommended implementation checks; none were executed in this read-only assessment.

- Exact native positives for both metabolite bodies and the reaction body, including whitespace normalization and empty synonyms; original source and companion hashes must remain bound.
- Wrong host, HTTP, model endpoint, collection endpoint, query/fragment/encoded ID, type mismatch and case-mismatched native ID.
- HTML/error JSON, duplicate name/bigg_id keys, nested duplicate keys, top-level list/results, malformed UTF-8/JSON, NaN, missing/empty/non-string/ID-only native name.
- Metabolite body submitted as reaction and vice versa; hybrid opposing markers; native model body with correct ID/name but results/model_bigg_id; non-Boolean pseudoreaction.
- Missing/wrong companion hash, wrong official version URL, duplicate version keys, wrong api_version, invalid last_updated/date, manifest release mismatch and version companion mismatch outside the selected corpus.
- Conflicting native names and cross-class same-ID collisions both inside and outside corpus selection; matching duplicates retain deterministic first provenance.
- Requested old identifier or external xref remains unresolved; nested metabolite names do not emit terms; changed old_identifiers does not create accepted name aliases.
- A missing BiGG source, wrong record label and an empty configured BiGG namespace remain blocking. Failed extraction must not replace an existing snapshot.
- acmana still has no exact CHEBI:17122 equivalence claim; universal reversibility does not override the separately cited forward iML1515 model context.
