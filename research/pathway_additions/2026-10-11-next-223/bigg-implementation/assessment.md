# Bounded BiGG authority adapter

The external adapter is ready for independent implementation review. It supports exact native universal metabolite and reaction identities/names using two explicit source kinds and a canonical BiGG policy, with no aliases or contextual waiver.

All 657 focused authority/identifier tests and lint passed. Three authentic universal originals and their native database-version companion were verified. Twelve controls derived from authentic bodies were rejected through the real CLI, preserving an existing output or leaving an absent output absent.

The full 629-original baseline reproduces every retained 2,265 term and 476 source metadata entries exactly. Adding three universal entries and their shared version companion produces 2,268 terms and 479 metadata entries, preserving all prior values. The manifest has 632 entries; four new original bodies include the shared version response. All originals were rehashed before and after, and all 439 copied maintained inputs remain unchanged.

Each BiGG entry requires an exact issuing HTTPS API URL and a version_source descriptor with relative cache path, official database_version URL and SHA-256. The validated native release must agree with `BiGG Models 1.6.0; retrieved 2026-10-11`; update timestamps remain unaltered and no timezone is inferred. The manifest retains companion linkage while existing source metadata stays unchanged. The adapter rejects HTML/errors, duplicate JSON keys, invalid UTF-8, collection/model bodies, mismatched ID/class, invalid names and conflicting source/version observations before corpus filtering.

The adapter exports no chemistry, stoichiometry, model bounds, gene rules or cross-database mappings. acmana's InChIKey discrepancy remains explicit. Universal ACMANAptspp reversibility and iML1515 forward context are not equated. Old identifiers do not become name synonyms. The current API snapshot is grounded in exact observed bytes and receipts, not claimed to be an immutable release URL.

Two failed preparations remain preserved: initial lint wrapping and a missing-ID test-fixture expectation; then a harness that expected historical retention from the current corpus alone. Both initial full CLI projections were correct, but the full retained scope requires the 21 unused historical IDs, as the existing canonical pipeline does. The successful successor uses that explicit IDs-only selection. Earlier outputs and exact attempted code/test inputs were not rewritten.

Only four proposed maintained files change: source builder, identifier policy, identifier documentation and a new test file. No maintained file, shared cache, Git or GitHub state was changed. The separate complex-name and endpoint implementations are not included. Root owns independent code review, shared-file composition, adoption, the actual merged223 bridge, complete-record authority generation and maintained gates.

Use `file-scope.json` for expected before/after hashes and `change.patch.json` for a lossless stageable patch archive. The plain patch remains external so its legitimate context prefixes are not stripped to satisfy staged whitespace checks. `proposal-retention-v2/new-source-entries.json` contains the exact three proposed entry objects. No full biological draft is adopted by this package.
