# NAD provenance serialization correction

This external proposal addresses [issue 487](https://github.com/CultureBotAI/PathwayMech/issues/487), stable key `nad-complex-provenance-key-order`. It changes precisely `src/pathwaymech/ecocyc_complex.py` and `tests/test_ecocyc_complex_authority.py`. The maintained worktree, authority snapshots, scientific record, rendered page, source cache, history and existing reviews have not been edited.

The prior module iterates a set to construct provenance dictionaries. Python hash randomization can therefore change the serialized order of the outer complex metadata and nested PC-1 class proof. The candidate uses the immutable tuple `("license", "url", "version", "sha256")`, matching the existing NAD snapshot, at all four comprehensions. Closed-field checks still use the same four-element set and keep their existing strict union/equality semantics. No accepted XML shape, scientific identity, provenance value, label or coefficient changes.

The new regression serializes unnamed and synonym-only/PC-1 fixture metadata in five fresh Python processes with hash seeds 0, 1, 2, 3 and 42. It compares unsorted JSON bytes, asserts exact outer and nested field order, and checks all metadata values against the in-process result. The original runtime fails at cross-process byte equality. The corrected runtime passes all 173 tests in the authority test module. The focused runner injects only the external candidate module; all other imports use the unchanged NAD working tree. Candidate subprocesses explicitly load that exact module file.

The additional bounded replay uses complete issuing CPLX0-682, PYRNUTRANSHYDROGEN-CPLX and PC-1 XML originals, checks their manifest hashes before and after reading, and reproduces both maintained NAD source metadata objects and terms byte-for-byte under the same five seeds. The expected serialization comes from the maintained snapshot, without sorting keys. This is a two-complex extraction, not a full native authority build.

Actual failures are retained. The first harness omitted the parent of pytest's external basetemp, so both initial exits were setup failures, not scientific/runtime evidence. `checks-successor/baseline-regression.stdout` is the subsequent real negative regression. The candidate then passed 173 tests. The initial external lint invocation treated the partial candidate package as third-party; the final no-cache check declares `pathwaymech` and `scripts` as first-party to match the maintained layout, without changing the candidate. A further exploratory source-root-only lint check also failed and is described in `execution-summary.json`. Final lint and format checks pass. These controls did not run the full maintained test suite or other full gates.
